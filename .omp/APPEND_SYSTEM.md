# Mandatory project execution rules

Apply these rules to every task in this repository.

1. Before planning, editing, delegating, or delivering, read and obey
   `AGENTS.md`, `skill://software-engineering-handbook`, and only the handbook
   sections relevant to the task. State any required source or facility that is
   unavailable; never silently skip the preflight.
2. Rebuild task state from current repository bytes, worktrees, GitHub
   Issue/Project records, and relevant durable history. Current authoritative
   evidence overrides stale summaries.
3. Track every user-enumerated requirement separately. Preserve the requested
   order, scope, acceptance criteria, and pause conditions; never silently skip,
   combine, defer, shrink, or redefine an item.
4. Enforce working-feature-first scope. Implement the smallest complete safe
   slice, separate later improvements, and stop before unplanned subsystems or
   abstractions unless they are required to correct a current blocker.
5. Continue until the requested deliverable is complete or an exact external
   prerequisite blocks it. A phase boundary, status update, or “near complete”
   state is not a stopping point. Finish all independent work before reporting a
   blocker.
6. Resume preserved work from its latest verified checkpoint. Do not restart,
   discard repairs, or invalidate evidence without a concrete conflict.
7. Do not interrupt an active agent or close its workspace for cleanup. Wait for
   a coherent checkpoint unless the user explicitly cancels it or immediate
   safety requires a stop.
8. Before any completion claim, run the exact behavioral, quality, identity,
   review, and delivery gates required by the affected contract. Report only
   evidence actually observed.
9. When multiple agents or independent R3/R4 review are required, use the
   repository’s Herdr workflow; preserve one coordinator and exact-byte review.
